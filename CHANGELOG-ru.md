# История изменений

В этом файле документируются все существенные изменения проекта.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), а проект использует [семантическое версионирование](https://semver.org/lang/ru/).

## [Не выпущено]

## [2.1.0] - 2026-09-28

### Добавлено

- Самостоятельные стратегии для ansible-core 2.14–2.18, 2.19–2.20 и 2.21: строгие проверки версий, адаптация API handlers/results, доверие к шаблонам и блокировка lookup в новом движке.
- Интерактивные проверки на двух hosts и генератор вариантов; исходный файл для 2.12–2.13 не изменён.

## [2.0.0] - 2026-09-25

### Изменено

- Для поиска имён переменных по glob теперь обязателен префикс `glob=PATTERN`; `regex=REGEXP` остаётся явным. Квадратные скобки без префикса всегда означают индексацию Jinja, операторы вычисляются как выражения. Замените `v role_*` на `v glob=role_*`.
- Дополнены русская и английская документация: правила glob, примеры и переход на новый синтаксис.

## [1.3.1] - 2026-09-25

### Исправлено

- Индексация в квадратных скобках, например `groups[tg]` и `groups[tg][0]`, вычисляется как выражение Jinja, если корень — переменная-контейнер; glob-классы вида `role_[ab]` продолжают работать.

## [1.3.0] - 2026-09-25

### Добавлено

- Добавлены alias `var`/`var!` и выражения Jinja с фильтрами и несколькими переменными для `vars`, `v` и `var`; выражения вычисляются в контексте выбранного host с отключёнными lookups.
- Обновлены документация команд и диаграммы потока переменных.

## [1.2.0] - 2026-08-25

### Добавлено

- Добавлены `r!`/`run!` для выполнения одной выбранной task с отключённым task-level `no_log`, явным warning о раскрытии секретов и без изменения исходной task.

## [1.1.0] - 2026-08-24

### Добавлено

- Добавлены `ra`/`run-all` для полного выполнения дерева dynamic `include_tasks` или `include_role` с последующим возвратом обычных остановок task.
- Добавлен короткий alias `a` для маскированной команды `args` в обычном prompt task.
- Добавлен плоский и древовидный просмотр tasks с фильтрами по host, regexp, role и tag; runtime-потомки dynamic includes дополняют каталог после раскрытия.
- Добавлена команда `break pick TASK_ID` для точного breakpoint по UUID, выбранного в task-browser.

### Исправлено

- Каждая явная meta-task теперь открывает один prompt inspector для своей активной lockstep-группы hosts и может быть пропущена без влияния на неявные lifecycle-tasks Ansible.

## [1.0.0] - 2026-08-21

### Добавлено

- Интерактивная стратегия `inspect_step` на основе штатной стратегии `linear` и механизма `--step` Ansible 2.13.
- Управление task через `r`/`run`, `s`/`skip` и `c`/`continue` без последующих остановок.
- Post-failure prompt для явного игнорирования необработанной ошибки task и продолжения play для затронутых hosts.
- Автоматический preview определения task с маскированием и команда `w` для повторного вывода.
- Единая безопасная команда `vars` с полным коротким alias `v`: точные имена, вложенные paths mappings/JSON/sequences, glob, явный `regex=REGEXP`, `host=HOST`, `depth=N` и явно немаскированные варианты `vars!`/`v!`.
- Просмотр с учётом host и команда списка hosts play после обработки inventory и `--limit`.
- Просмотр исходных и templated-аргументов task в безопасном и явно немаскированном режимах.
- Вычисление составных Jinja-выражений для default или явно выбранного host с форматированием структур и отключёнными Ansible lookups.
- Явное вычисление `eval-lookup` для одного host с включёнными Ansible lookups, warning перед каждым вызовом, форматированным немаскированным выводом и без режима watches или cross-host.
- Вычисление Jinja-выражения для всех hosts через `eval-all` с возможностью сворачивания одинаковых значений.
- Предварительное вычисление conditions `when` для одного host или всех hosts текущей task.
- Host-aware preview items современного `loop` и legacy `with_*`, включая metadata `loop_control`, ограничение глубины, маскированный и явно немаскированный вывод.
- Контекст одного item loop для вычисления Jinja-expression, `when`, templated-аргументов task или template без выполнения item.
- Просмотр результата предыдущей task с учётом host и глубины в маскированном и явно немаскированном режимах.
- Локальные для процесса watches, автоматически выводимые на интерактивных остановках.
- Breakpoints по regexp имени task, точному имени role и tag с выполнением через `go`.
- Host-specific preview результата `ansible.builtin.template` на экране или в защищённом локальном файле.
- Рекурсивное эвристическое маскирование распространённых имён ключей секретов.
- Runtime-изменение top-level переменных для всех hosts play или одного выбранного host.
- История команд readline и редактирование строки клавишами управления курсором, если модуль доступен.
- Запускаемый пример с двумя hosts для facts, переменных role, `set_fact`, `register`, templates, handlers, разных loop items, `loop_control`, conditions и помеченной tag цели breakpoint.
- README, подробные руководства, changelogs и архитектурные PlantUML-диаграммы на английском и русском языках.
- Полное описание на русском и английском языках поведения `--check`, прогнозируемых результатов, неподдерживающих режим модулей, controller-side эффектов и семантики команд inspector.
- Вывод версии при запуске: `inspect_step version 1.0.0`.
- Проверка совместимости при запуске: статус поддерживаемого диапазона, warning о неполной совместимости для версий ниже 2.12 и понятная ошибка несовместимости для 2.14 и новее.

### Исправлено

- Одинарные и двойные кавычки вокруг значения breakpoint теперь используются для группировки и не становятся символами pattern.
